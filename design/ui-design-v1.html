影软小铺 · 微信小程序界面设计稿

本稿覆盖 6 项核心能力：微信登录、商品详情、按类目检索、自助下单、自动发货、订单查询与客服。视觉沿用现有 wx-auto-deliver 的绿色主色（#12B76A）与卡片式布局，保证与已完成的云开发代码风格一致，可直接映射为 WXML 结构。

页面数 11 TabBar 4 设计基准 750rpx 主色 #12B76A 后端 云开发 + faka 3.8.4

01 / 页面跳转关系

实线为主动线（编号 ①–⑤），虚线为辅助入口。首页 / 分类 / 订单 / 我的 为 TabBar 常驻页，任意页面可返回。
主流程 ① 微信授权 → ② 点击商品 → ③ 立即购买 → ④ 提交并支付 → ⑤ 查看订单 辅助入口（Tab 切换 / 搜索 / 客服）

02 / 界面设计

11 个页面。每屏均标注小程序路径与关键交互，可直接对应 app.json 的 pages 数组。

03 / 页面与接口映射

左侧为小程序页面与动作，右侧为具体数据来源。云函数承担「鉴权 + 聚合 + 密钥隔离」，AppSecret / AppKey 绝不进小程序包。

04 / 编码前需你确认的 4 个决策

这 4 项决定数据流向与后台配置量，界面本身不随选择变化（仅支付按钮文案与结果页分支不同）。

A支付通道（最关键）

推荐：微信虚拟支付。faka 的 order/trade 返回的是 H5 收银台，小程序内无法打开第三方支付域名，绕道扫码收款会被审核驳回。

代价：需在 MP 后台按商品逐个建「道具」，道具 ID 与价格须与 faka 一致（现成代码见 cloudfunctions/vpay）。

B商品与卡密数据源

推荐：云数据库为主，faka 定时同步商品。faka 无卡密导出 API，卡密池只能在云数据库维护。

好处：下单、发货、补发全在云开发闭环，不依赖 faka 在线；坏处：上新商品要同步两处（可用云函数一键抓取商品名/价格/封面，减少手工）。

C登录强度

推荐：静默 openid 登录 + 手机号选填。首屏不拦截授权，进详情页才展开口令。

手机号仅用于「换设备找回订单」，不做强制，可把首单转化率提高一档。

!合规红线

历史记录中的「琅琊榜第1部」属影视资源，无授权销售会被支付通道关停并承担侵权责任。上线前须把在售商品全部换成原创或已获授权的数字内容，否则虚拟支付审核也过不了。
